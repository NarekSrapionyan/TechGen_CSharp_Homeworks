## 2.3 Decimal type and precision

PostgreSQL uses `numeric` for an unconfigured C# `decimal`. Setting the precision explicitly is still useful because it defines how many digits can be stored and how many of them are after the decimal point. It also makes the database schema more predictable.

In this project `Price` is configured as:

```sql
"Price" numeric(10,2) NOT NULL
```

## 3.3 Generated key

`BookId` is `0` before `SaveChanges()` because `0` is the default value of an `int` in C#. The key has not been generated by PostgreSQL yet.

After `SaveChanges()` the first `BookId` becomes `1`.

PostgreSQL returns the generated key to EF Core with:

```sql
RETURNING "BookId";
```

## 4.5 Any vs Count

`Any()` generated a query using `EXISTS`:

```sql
SELECT EXISTS (
    SELECT 1
    FROM "Books" AS b
    WHERE NOT (b."IsRead"))
```

`Count()` generated:

```sql
SELECT count(*)::int
FROM "Books" AS b
WHERE b."IsRead"
```

`Any()` is better when we only need to know if at least one matching row exists. It does not need to calculate the total number of matching rows.

## 4.8 Paging

The paging query generated `LIMIT` and `OFFSET`:

```sql
ORDER BY b."Title"
LIMIT @__p_0 OFFSET @__p_0
```

In this case both parameter values were `3`, because the program skips the first three books and takes the next three.

Paging without `OrderBy` is meaningless because there is no guaranteed order of rows. Without a stable order, there is no reliable definition of the first or second page.

## 4.11 Contains vs ILike

The query using:

```csharp
b.Author.Contains("martin")
```

generated `LIKE`:

```sql
WHERE b."Author" LIKE '%martin%'
```

It returned `0` rows because the comparison was case-sensitive.

The query using:

```csharp
EF.Functions.ILike(b.Author, "%martin%")
```

generated:

```sql
WHERE b."Author" ILIKE '%martin%'
```

It returned `3` rows: Robert Martin, Martin Kleppmann and Martin Fowler.

On SQL Server with its default case-insensitive collation, the first version would normally also match these names.

## 5.1 Updating a book

Before changing `IsRead`, the entity state was:

```text
Unchanged
```

After changing it, the state was:

```text
Modified
```

The generated update was:

```sql
UPDATE "Books" SET "IsRead" = @p0
WHERE "BookId" = @p1;
```

Only `IsRead` appears in the `SET` clause.

EF Core knew that this property changed because it tracks loaded entities and their original values. When `SaveChanges()` is called, EF compares the current values with the original values and detects what changed.

## 5.4 Written questions

### 1. Query building and execution

Methods such as `Where`, `OrderBy`, `Select`, `Skip` and `Take` build an `IQueryable`. They describe the query but do not execute it yet.

For example:

```csharp
var books = db.Books
    .Where(b => b.Year > 2005)
    .OrderBy(b => b.Title)
    .ToList();
```

`Where` and `OrderBy` build the query. `ToList()` executes it and sends the SQL to PostgreSQL.

Other operations used in the project that execute queries include `First()`, `Any()`, `Count()` and `Sum()`.

### 2. Number of SELECT statements

The exact number of `SELECT` statements will be counted from the final full-run SQL log.

### 3. SaveChanges

Changing a C# property does not immediately send an SQL command to PostgreSQL.

EF Core tracks the entity and its changes in the `DbContext`. `SaveChanges()` is the point where EF Core sends the required `INSERT`, `UPDATE` or `DELETE` commands to the database.

This also allows several changes to be saved together instead of sending a database command every time a property is changed.

## 7.1 UTC timestamps

I tried to save a book using `DateTime.Now`.

The exception was:

```text
Cannot write DateTime with Kind=Local to PostgreSQL type 'timestamp with time zone', only UTC is supported. Note that it's not possible to mix DateTimes with different Kinds in an array, range, or multirange. (Parameter 'value')
```

The `AddedAt` column is:

```sql
"AddedAt" timestamp with time zone NOT NULL
```

`timestamp with time zone` represents an instant in time. Npgsql requires a UTC `DateTime` for this mapping and rejects a value whose `Kind` is `Local` or `Unspecified`.

One solution is to use:

```csharp
DateTime.UtcNow
```

Another solution is to convert a local value to UTC before saving it:

```csharp
date.ToUniversalTime()
```

After catching the exception I used `db.ChangeTracker.Clear()` so the failed entity would not remain tracked and affect later saves.

## 7.2 PostgreSQL identifiers

The first query:

```sql
select * from books;
```

failed with:

```text
ERROR: relation "books" does not exist
```

The second query:

```sql
select * from "Books";
```

worked.

PostgreSQL converts unquoted identifiers to lowercase, while quoted identifiers preserve their case. EF Core generated the table as `"Books"`, so raw SQL must use the correct quoted name.

A team could configure a lowercase or snake_case naming convention from the beginning to avoid this problem when writing raw SQL.

## 7.3 Generated DDL

The generated PostgreSQL definitions were:

```sql
"BookId" integer GENERATED BY DEFAULT AS IDENTITY,
"Price" numeric(10,2) NOT NULL,
"IsRead" boolean NOT NULL,
"AddedAt" timestamp with time zone NOT NULL
```

With SQLite the definitions would be different because SQLite has different type mapping rules.

`BookId` would use SQLite integer primary-key behavior instead of PostgreSQL identity syntax. Key generation is provider-specific.

`Price` would not have PostgreSQL's `numeric(10,2)` behavior. SQLite does not enforce decimal precision and scale in the same way.

`AddedAt` would not use `timestamp with time zone` because SQLite does not have a native timestamp-with-time-zone type.

`IsRead` would not use PostgreSQL's native `boolean` type. SQLite commonly stores Boolean values as integers such as `0` and `1`.

## 7.4 Server-side grouping

The query groups books by author and calculates the number of books and total price for every author.

The SQL log should contain a `GROUP BY` clause. This proves that the grouping was performed by PostgreSQL instead of loading all books and grouping them in C# memory.

If EF Core cannot translate a `GroupBy` expression into SQL, the query fails with a translation error. The query then needs to be rewritten into a form that EF Core can translate.
